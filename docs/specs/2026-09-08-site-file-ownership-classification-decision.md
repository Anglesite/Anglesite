# Site file ownership: what lives in `Source/` versus `Config/`

**Date:** 2026-09-08
**Status:** current
**Issue:** #1960 (decision D6 of [`2026-09-08-product-direction-review-decisions.md`](2026-09-08-product-direction-review-decisions.md))

## Decision

A `.anglesite` package has two homes for app-written files, and every file the app writes into
a site is classified into exactly one of them by a single question: **does it describe the
site, or does it describe the infrastructure Anglesite provisioned for it?**

- **Content** — anything that describes the site: what it says, how it looks, what it is for,
  and the build inputs the template's own scripts read. Content lives in `Source/`, is committed,
  and travels with every clone (git is the source of truth, #72). An external tool editing a
  clone must see it.
- **Config** — anything that describes infrastructure Anglesite manages on the owner's behalf
  (D1) or the app's own bookkeeping about a deploy. Config lives in `Config/`, is never in git,
  and a clone built anywhere else neither needs it nor should carry it.

The test that settles a borderline case: *if this file were committed and the owner deleted the
Cloudflare account, would the repo still be a correct description of the site?* Infrastructure
identifiers fail that test; everything the template's build reads passes it.

## Consequences

- Existing sites migrate on open under the #745 mechanism — `DeployStateRelocation` moves
  `Source/wrangler.toml` to `Config/`, copies the three markers into `SiteSettings` and strips
  them from `.site-config`, adds `wrangler.toml` to `.gitignore`, and hands the touched paths
  (including the *removal* of `wrangler.toml`, which `ExistingSiteMigrationCommitter` now stages
  as a deletion) to the same batch commit every other migration step uses. It never asks: the
  app knows where its own state belongs.
- `AnglesitePackage.currentFormatVersion` is **not** bumped. The marker's contract is "bump
  when older builds can't safely write"; an older build opening a migrated package writes
  `Source/wrangler.toml` again, but the migrated `.gitignore` keeps it out of the repo, and it
  re-runs the Worker-name collision check because it can't see the markers — a spurious rename
  prompt at worst, never leaked infrastructure state. A format bump would refuse the package
  outright in every older build, which is a heavier cost than that.
- `configDirectory` is required, not optional, through `DeployCommand.deploy`,
  `DeployTargetContext`, `DeployTarget.authorize`, `ContainerDeployExecutor` and
  `ContainerCommandRunner`. Deriving `Config/` from `Source/` inside those seams was
  considered and rejected: a derived sibling path is unsafe in any caller that isn't a real
  package (every test suite that deploys against a bare temp directory would share one
  `$TMPDIR/Config`), and explicit threading is the convention the rest of the codebase already
  follows.
- Every writer of `settings.plist` during a deploy goes through `SiteConfigStore.update`
  (read-modify-write) rather than saving a deploy-start snapshot — the markers, the source-bundle
  commit and the provisioned-resource ids are all written by different actors during one deploy,
  and the last stale-snapshot save used to drop the others.
